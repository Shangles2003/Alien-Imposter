**In-game performance (partly done):** the two causes of "clicks take a second / glitch" are in `src/services/gameSync.ts`: (1) `submitPlayerAction`/`applyGameAction` do a `fetchGameState` THEN a write — two sequential round-trips per action; (2) the realtime subscription re-fetched the whole game on every change. Fixed (2): `subscribeToGame` now uses the `postgres_changes` payload (`payload.new.state`) directly with a `load()` fallback, cutting a round-trip off every observer update. The acting player was already optimistic (`useOptimisticGameActions`). STILL OPEN if more speed needed: cut the write-path pre-fetch via optimistic-concurrency (add a `version` column + CAS + retry) — kept the pre-fetch for now because it guards concurrent per-player writes (e.g. simultaneous chamber submissions) from clobbering.

**PROMPT localization — ARCHITECTURE BUILT (translations pending).** The per-player-language plumbing is done and shipping (English-only for now, zero visible change):
- **Stable ids:** `src/game/promptId.ts` — `promptContentId(chamber, parts)` = chamber-prefix (`op/dl/dr/wr/ml`) + djb2/base36 hash of the English source (U+001F-joined). Reorder-proof; editing English text re-keys that prompt (orphans its translations → English fallback). `ChamberPrompt.promptId?` added.
- **Stamping:** `getPromptForChamber` sets `promptId` on catalog picks only; **custom-deck picks get no id** (stay in the author's words). most_likely hashes the name-agnostic template.
- **Resolver:** `src/i18n/prompts.ts` — `localizedPromptForPlayer()` + `localizedPromptOptions()`, keyed by `promptId` × current `i18n.language`, **English fallback** when absent (and always for `en`). `registerPromptLocale(locale, entries)` is the drop-in point for translation packs; `CATALOG` is empty today. Refactor: `getPromptForPlayer` now sits on `promptVariantForPlayer` (`human|alien|scenario`).
- **Only render site:** `ChamberViews.tsx` (live task screen) uses the resolver. `promptShown` is stored but **never displayed** (log/reveal show answers only via `formatChamberAnswer`), so no engine/serialization/log changes were needed.
- **Catalog + guard:** `scripts/prompt-catalog.js` transpiles `prompts.ts`+`betrayal.ts`, emits `src/i18n/prompts/en.json` (promptId → {human, alien, scenario?, options?}) and **asserts id uniqueness (fails on collision)**. Current: **395 unique pairs** — opinion 82, deliberation 51 (w/ scenario+options), drawing 100, writing 81, most_likely 81. `tsc` clean.

**Translation packs — how they load:** a translated locale is `src/i18n/prompts/<locale>.json` (promptId → {human, alien, scenario?, options?}, same shape as en.json). `src/i18n/promptPacks.ts` imports each and calls `registerPromptLocale(code, data)`; it's side-effect-imported in `app/_layout.tsx` right after `@/i18n`. To add a language: create the JSON, add two lines to promptPacks.ts. Validate with `node scripts/validate-prompt-locale.js <code>` (checks key parity, non-empty human/alien, scenario presence, options length, and that `wr_` prompts keep the `___` blank). **Proven:** the runtime TS `promptContentId` yields IDs byte-identical to the generator's en.json keys (verified across opinion/deliberation/most_likely), so lookups resolve.
