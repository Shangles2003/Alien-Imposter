Alien Imposter is free-to-play with one optional paid unlock, the **Expansion Pass** (iOS only for now, Aug 2026 launch). One RevenueCat entitlement (`premium`) is granted by EITHER an auto-renewing monthly subscription (`premium_monthly`, $0.99/mo) OR a one-time non-consumable (`premium_lifetime`, $9.99, permanent). Both unlock the same thing.

**What premium unlocks:** 3/5/7-stage games (free = 5 only), the full prompt library (free = a fixed ~10% sample per chamber, see `FREE_SAMPLE_RATIO`/`FREE_SAMPLE_MIN` in `src/game/prompts.ts`), and the **Betrayal Pack** (`src/content/packs/betrayal.ts`) — a premium expansion of family-friendly friend-group prompts, host-toggled in `HostSettingsPanel`. Premium ownership = `ownedPacksForPremium(hasPremium)` in `src/content/types.ts` (`['core','betrayal']`). Imposter counts are player-count based and identical for both tiers.

**Prompt sources are multi-select + merged (not exclusive):** premium hosts get three independent toggles in `HostSettingsPanel` — Base Prompts (core), Betrayal Pack, My Custom Deck. `getPromptForChamber` MERGES every enabled source per chamber (custom + packs), with a core fallback if a chamber ends up empty. The base pack is toggleable off. Guards: never zero sources; custom-only requires ≥7 custom prompts (UI guard via `customCount` + a `startGame` backstop that re-adds core). `normalizeHostSettings` no longer force-adds core; `sanitize` only re-adds core when there'd be no source at all.

**Manual comp grant:** `profiles.premium_grant` boolean (migration `supabase/migrations/20260708_premium_grant.sql`) OR'd into premium access. Set it from the dashboard (`update profiles set premium_grant=true where username='x'`); a trigger blocks normal users from self-granting (only null/service_role callers can change it). Flows: `getProfile`→`PlayerProfile.premiumGrant`→`PremiumContext` effect→`premiumService.setGrant`→`hasPremiumAccess`. Settings shows "Granted (comp account)".

**Premium gating hardened (was granting everyone premium):** `hasPremiumAccess` now honors `devUnlock` only when `__DEV__`, and `storeUnavailable` full-access only OFF iOS (iOS with a missing key defaults to FREE, not premium). Settings shows a clear FREE/PREMIUM banner.

**Apple users get a generated username:** `signInWithApple` assigns a unique username (e.g. `joseph4821`) on first sign-in — the block/report system (`block_user_by_username`) needs it. `AuthContext.refreshProfile` now re-fetches the live session user (fixed a race where the profile came back null right after Apple sign-in, breaking Host Party until re-login).

**Sign in with Apple (built, code-complete):** `signInWithApple()` in `src/services/auth.ts` (uses `expo-apple-authentication` + `supabase.auth.signInWithIdToken`), `AppleSignInButton` on login/signup screens (iOS-only, auto-hides elsewhere), `app.json` has `ios.usesAppleSignIn:true` + the `expo-apple-authentication` plugin. Added ALONGSIDE username/password (not replacing). A DB trigger (`handle_new_user`) auto-creates the profile as "Crew Member"; the service upgrades that to the Apple first name on first authorization only. STILL NEEDS external setup before it works: Apple Developer App ID "Sign in with Apple" capability + Supabase Auth → Providers → Apple enabled with bundle id `com.tornari25.alienimposter` in Authorized Client IDs, plus a fresh native build. Note: premium was ALREADY Apple-ID-recoverable via Restore regardless of login — Apple sign-in is about recovering the account *identity* without email.

**Custom deck builder (built):** premium, cloud-stored, ONE personal deck per user. Table `custom_prompts` (migration `supabase/migrations/20260708_custom_prompts.sql` — user must run it). Service `src/services/customDecks.ts` (fetch/add/delete, profanity-filtered on save). Builder UI `src/components/premium/DeckBuilder.tsx` at route `app/deck.tsx` (entry: main-menu "Custom Deck" button + Host Settings "My Custom Deck" toggle). All 5 task types, authored as crew/imposter pairs (deliberation also takes scenario + options). `HostSettings.useCustomDeck` gates it; at `startGame` the host's prompts are fetched and baked into `GameState.customPrompts`, and `getPromptForChamber` PREFERS custom per chamber (chambers with no custom prompts fall back to enabled packs). Testable in Expo Go once the table exists (no native build needed). Next: could add multiple named decks later (currently one personal deck).

**Host-authoritative gating (key design):** only the HOST needs the Expansion. `sanitizeHostSettingsForEntitlements` (`src/content/types.ts`) clamps `missionCount` + `fullLibrary` to the host's entitlement; `startGame(lobbyId, hostId, hasPremium)` re-sanitizes with the host's LIVE entitlement at launch and bakes `fullLibrary` + `contentPacks` into game state, so everyone in that host's lobby gets the expanded game for the session.

**Entitlement plumbing:** `src/premium/PremiumService.ts` (RevenueCat, lazy-loads the native SDK via `require` so Expo Go never touches it) → `src/context/PremiumContext.tsx` (live provider, was previously an all-free stub) → `usePremium().hasPremiumAccess`. RevenueCat appUserID = Supabase user id, so premium follows the account. On Expo Go it's mock (dev-unlock toggle in Settings simulates premium); on a real build with no store key for the platform (Android now) it grants full access rather than show a dead paywall.

**Still requires the user's setup (not code):** App Store Connect paid-apps agreement + the two products with those exact IDs; a RevenueCat project with entitlement `premium` and an offering exposing both packages; `EXPO_PUBLIC_REVENUECAT_IOS_KEY` env var; an EAS/TestFlight build (IAP can't run in Expo Go). Legal ([[../src/legal/terms-of-service-content]] TOS §6 + privacy policy) were updated for IAP — should get a human/legal review.
